# contributing

## workflow
- create a feature branch from main
- keep pr scope small and focused
- link to relevant issues or prd sections

## commit messages
- use imperative mood (e.g., "add edge case model")
- include a short scope if helpful (e.g., "api: ...")

## code style
- web: eslint + prettier
- api: ruff + ruff format
- run lint and tests before opening a pr

## reviews
- at least one reviewer required
- update docs when behavior changes (see `docs/index.md`)
