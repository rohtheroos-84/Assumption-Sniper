# Assumption Sniper v1.0.0 — Release notes

**Release date:** 2026-06-16  
**Codename:** Production ready

## Overview

First production-ready release of Assumption Sniper: an AI-powered cognitive debugging platform that decomposes ideas into assumptions, stress-tests them with multi-agent critiques, simulates edge cases, scores risk, and reconstructs stronger versions.

## Highlights

### Core product

- Full analysis pipeline: decomposition, skeptic critiques, edge-case simulation, reconstruction, and risk scoring
- Interactive dashboard with assumption graphs, critique lists, and reconstruction comparison
- Demo mode and landing page for prospects
- Private beta program with invite codes and in-app feedback

### Platform

- FastAPI backend with PostgreSQL and Redis
- Next.js web app with streaming run progress
- OpenRouter integration with cost/quality/balanced routing profiles
- JWT auth, API keys, and project-scoped access control

### Reliability and performance

- Request queue, batching, pagination, and circuit breakers
- Cache warming and load-test baseline (`docs/observability/perf-baseline.json`)
- SLOs and Prometheus metrics with Grafana dashboard and alert rules

### Security and compliance

- Input sanitization, output filtering, audit logs, retention purge
- Rate limiting, secret rotation support, CI security scans (bandit, pip-audit, Trivy)
- Documented permissions model (`docs/security/permissions.md`)

### Operations

- Docker images, compose stacks for dev/staging/production
- CD workflow with smoke tests, migrations, blue/green deploy, rollback scripts
- Runbooks, on-call rotation, and completed incident drill

## API surface (v1)

- `POST /api/v1/runs` — start analysis
- `GET /api/v1/runs/{id}` — run status and results
- `GET /api/v1/metrics` — Prometheus exposition
- Auth, beta, feedback, and analytics endpoints — see `docs/architecture.md`

## Breaking changes

None — initial public API version.

## Upgrade notes

1. Copy `.env.example` to environment-specific templates under `deploy/env/`.
2. Run `python apps/api/scripts/migrate.py` before serving traffic.
3. Import observability assets from `docs/observability/`.
4. Complete `docs/deploy/launch-checklist.md` before production cutover.

## Known limitations (v1)

- No team collaboration or SSO
- No web-search validation of assumptions
- Redis queue state is ephemeral
- Eval dataset is keyword/theme based, not live LLM regression in CI
